# SoulSync — Jain Matrimony app

Expo (SDK 58) / React Native app built from the Claude Design handoff
(`project/Jain Matrimony App v2.dc.html`), wired to the NestJS backend
[`Rushabh2397/jain_matrimony_backend`](https://github.com/Rushabh2397/jain_matrimony_backend).

Defaults are the final design picks: **Peacock** palette (4e), **bandhani** logo (3c),
**number + bars** match score (3h), **Baloo 2** display font, welcome screen **5c** with the thin
folded-hands **Jai Jinendra** mark (6a). UI text uses the system font (SF Pro / Roboto).

## Run

```bash
npm install
npx expo start          # press i / a, or scan the QR code with a development build
```

The date picker, secure storage and image/document pickers are native modules, so use a
development build (`npx expo run:ios`, `npx expo run:android`, or `eas build --profile development`).

### Demo data vs. the real backend

- **No `EXPO_PUBLIC_API_URL`** → the app runs on the design's sample members (Priya, Neha, Kavya…),
  in memory. Any 6-digit code logs you in (Paste fills `482913`).
- **With the backend** → copy `.env.example` to `.env.local` and set
  `EXPO_PUBLIC_API_URL=http://<your-computer's-LAN-IP>:3000`. With `ALLOW_DEV_OTP=true` on the
  server, the code `123456` works.

## Hidden Theme lab

Long-press your profile card (Profile tab) to open it: the 6 palettes, custom colours, the 7 display
fonts and the petals score style from the design page. Choices persist on the device.

## Code layout

- `src/api/` — `types.ts` (app models + `Api` interface), `http.ts` (backend client: JWT + refresh,
  enum mapping, presigned uploads, socket.io chat), `demo.ts` (sample data), `enums.ts` (backend enum ⇄ design label).
- `src/theme/` — palettes, `color-mix(in oklab)` port, platform variables (`btnR`, `chipR`, `card`…).
- `src/components/` — controls, sheets/dialogs/toasts, score visuals, screen chrome, brand mark.
- `src/icons/glyphs.ts` — Material Symbols Rounded paths, generated by `npm run icons`.

## Known gaps

- **Family alerts** has no backend field yet; the switch is stored on the device only.
- **Chat list**: the backend's conversation list has no last message or unread count, so the app reads
  the latest 20 messages of each chat. A summary field on `GET /chat/conversations` would remove those calls.
- **Android OTP**: true zero-tap fill from WhatsApp needs WhatsApp's Android OTP SDK (native module);
  the app fills the code from the clipboard when the person returns from WhatsApp.
- **Blocked** shows a count only; the design has no blocked-list screen.
